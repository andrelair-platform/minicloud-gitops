# BMAD Workflow Standard

BMAD (Breakthrough Method of Agile AI-driven Development) is the story-authoring workflow for all ktayl-solution and platform development projects. This file defines the standard so any project on the platform can benefit from it.

## How it works end-to-end

```
1. Engineer/Claude writes story .md files → bmad/stories/<project>/<milestone>/
2. Files committed + PR merged to minicloud-gitops main
3. GitHub Action .github/workflows/bmad-sync.yml fires automatically
4. bmad-to-github.sh parses YAML frontmatter → creates GitHub Issues on platform-backlog
5. Issues attached to the correct Milestone + added to the project board
```

For new sprints: use the Backstage "New BMAD Sprint" template instead of step 1 — it scaffolds the story directory and opens the PR automatically.

## Directory layout

```
minicloud-gitops/bmad/
  templates/
    story-template.md           # copy this when writing new stories manually
  stories/
    <project-code>/             # e.g. cert-1, claims-service, portal, ai-assistant
      <milestone-slug>/         # e.g. m1-m2, m3-m5, sprint-1
        SPRINT-OVERVIEW.md      # sprint manifest (generated by Backstage template)
        S001-<slug>.md
        S002-<slug>.md
        ...
```

## Story ID convention

Format: `S<NNN>-<short-slug>` within each sprint directory (sequential per sprint, reset per sprint).

- `S001` to `S009`: core functional stories
- `S010` to `S019`: infrastructure, CI/CD, k8s manifests
- `S020+`: cross-cutting (security, observability, docs)

GitHub Issue title: `[S001-short-slug] Story title here` — the `[S001-short-slug]` prefix is mandatory. The bridge script adds it automatically. It enables idempotent re-runs (script searches `[S001-short-slug] in:title` to detect existing issues).

## Using the Backstage template

1. Go to `https://backstage.devandre.sbs` → **Create** → **New BMAD Sprint**
2. Fill in: project code, milestone slug, milestone title (must match GitHub Milestone title exactly), tech stack
3. Scaffolder generates story stubs and opens a PR on minicloud-gitops
4. Review and enhance the generated stories (add ACs, technical notes)
5. Merge → GitHub Action creates all issues on platform-backlog automatically

## Running the bridge script manually

```bash
cd ~/Developer/cloudplateform/minicloud-gitops

# Dry run first (always)
bash scripts/bmad-to-github.sh bmad/stories/<project>/<milestone> \
  --milestone "Milestone title matching GitHub exactly" \
  --dry-run

# For real
bash scripts/bmad-to-github.sh bmad/stories/<project>/<milestone> \
  --milestone "Milestone title matching GitHub exactly"
```

Defaults: `--repo andrelair-platform/platform-backlog` · `--project 1` (minicloud platform roadmap)

The script is **idempotent** — it skips stories whose `[S001-slug]` is already in an issue title. Safe to re-run after adding new stories to an existing sprint.

## Creating a GitHub Milestone before running the script

```bash
gh milestone create \
  --repo andrelair-platform/platform-backlog \
  --title "CERT-1 M3-M5 — ktayl-claims-service (Java)" \
  --description "Sprint covering claims service core"
```

The bridge script will print a warning and skip the milestone attachment if the title doesn't match an existing milestone exactly.

## Story YAML frontmatter reference

```yaml
---
id: S001-short-slug          # REQUIRED — used as GitHub Issue title prefix
title: "Full story title"    # REQUIRED — becomes the GitHub Issue title (after prefix)
status: Ready                # Draft | Ready | In Progress | Done
type: Story                  # Story | Bug | Spike
epic: project-slug           # free-form epic grouping
milestone: "Milestone title" # MUST match the GitHub Milestone title exactly
estimate: 3                  # story points (Fibonacci: 1, 2, 3, 5, 8, 13)
labels: [go, backend, cert-1] # must exist on platform-backlog or script creates them
priority: Must               # Must | Should | Could | Won't
assignee: AndreLiar
---
```

## Label conventions

| Label prefix | Purpose |
|---|---|
| Tech stack | `go`, `java`, `python`, `typescript` |
| Layer | `backend`, `frontend`, `devops`, `testing` |
| Project | `cert-1`, `claims-service`, `portal` |
| Type | `api`, `database`, `domain-logic`, `ci`, `gitops`, `security` |

The script auto-creates missing labels with a grey default colour. Add proper descriptions/colours later via `gh label edit`.

## GitHub Action behaviour

`.github/workflows/bmad-sync.yml` triggers on push to `main` when any `bmad/stories/**/*.md` file changes. It:
1. Detects which sprint directories had changes
2. Reads the milestone from the first story's frontmatter
3. Runs the bridge script for each changed directory

The action uses `GITOPS_TOKEN` (org-level secret, already set). It is idempotent — running it twice creates no duplicates.

## Official BMAD tools (Claude Code skills)

Install in any project repo:
```bash
npx bmad-method install --directory . --modules bmm --tools claude-code --yes
# Creates _bmad/ — add to .gitignore
```

| Phase | Tool | What it does |
|-------|------|--------------|
| Pre-sprint | `/bmad-forge-idea` | Adversarial pressure-test: hardened / killed / clearer |
| Sprint kick-off | `/bmad-sprint-planning` | Readiness gate (PASS/CONCERNS/FAIL) + sprint-status.yaml |
| Writing ACs / specs | `/bmad-advanced-elicitation` | Pre-mortem, red-team, first-principles |
| Architecture | `/bmad-party-mode` | Multi-agent design discussion |
| Research | `/bmad-deep-recon` | 6 research types × 3 modes (discovery/targeted/validation) |
| Story build | `/bmad-build` | Spec-driven loop: clarify → implement → review → report |
| Multi-story autonomous | `/bmad-build-auto` | Unattended loop; terminal statuses: blocked / done |
| Post-sprint | `/bmad-review` (via agent) | Evidence-based retrospective |

Named agents for co-authoring stories: `/bmad-agent-mary` (BA), `/bmad-agent-john` (PM), `/bmad-agent-winston` (Architect), `/bmad-agent-amelia` (Dev).
