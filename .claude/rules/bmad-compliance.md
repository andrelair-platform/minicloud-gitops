# BMAD Compliance — Pre-Implementation Gate

This rule is enforced before any story implementation begins, for every repo, every sprint.

## The Rule

**Never write implementation code for a story without first verifying the pre-sprint artefacts exist.**

If any artefact is missing, generate it (or guide the user to generate it with the right BMAD skill) before touching any code.

## Required Artefacts (per service/project repo)

| Artefact | Location | Generated by |
|---|---|---|
| `project-context.md` | `docs/project-context.md` | Manual (once per repo) |
| PRD | `_bmad-output/planning-artifacts/prd.md` | `/bmad-agent-pm` or `/bmad-prd` |
| Architecture doc | `_bmad-output/planning-artifacts/architecture.md` | `/bmad-agent-architect` or `/bmad-architecture` |
| Epics listing | `_bmad-output/planning-artifacts/epics.md` | `/bmad-create-epics-and-stories` |
| Sprint readiness gate | `_bmad-output/planning-artifacts/sprint-status.yaml` | `/bmad-sprint-planning` |

## Required Artefacts (per sprint, in minicloud-gitops)

| Artefact | Location | Generated by |
|---|---|---|
| Sprint manifest | `bmad/stories/<project>/<milestone>/SPRINT-OVERVIEW.md` | Backstage scaffolder or manual |
| Story files with YAML frontmatter | `bmad/stories/<project>/<milestone>/S*.md` | Backstage scaffolder or `bmad-to-github.sh` |

## Pre-Flight Check (run at session start for any implementation task)

```bash
# In the service repo:
ls docs/project-context.md
ls _bmad-output/planning-artifacts/{prd,architecture,epics,sprint-status}.{md,yaml}

# In minicloud-gitops:
ls bmad/stories/<project>/<milestone>/SPRINT-OVERVIEW.md
```

If any file is missing → STOP. Generate the missing artefact first:

| Missing | Command |
|---|---|
| BMAD not installed | `npx bmad-method install --directory . --modules bmm --tools claude-code --yes` |
| `project-context.md` | Create manually with: stack, compliance constraints, domain model, sprint state |
| PRD | `/bmad-agent-pm` → menu option PRD |
| Architecture | `/bmad-agent-architect` → menu option architecture |
| Epics | `/bmad-agent-pm` → menu option CE (Create Epics) |
| Sprint gate | `/bmad-sprint-planning` |
| `SPRINT-OVERVIEW.md` | Copy template from `bmad/stories/cert-1/m1-m2/SPRINT-OVERVIEW.md` and adapt |

## Story Status Lifecycle (enforce on every PR)

```
Draft      → story being written, not ready to implement
Ready      → story approved, ACs finalized, waiting for sprint slot
In Progress → implementation started, branch open
Done       → PR merged to staging, all ACs checked off
```

**Rules:**
1. Before opening a feature branch: set `status: In Progress` in the story `.md` file
2. On PR merge to staging: set `status: Done`, check off all `- [ ] AC-N:` items in the story file
3. Update `SPRINT-OVERVIEW.md` tracker table on both state changes
4. Commit the story status update in the same PR as the implementation (not a separate PR)

## BMAD Workflow (correct order, every sprint)

```
1. /bmad-forge-idea              → pressure-test product idea
2. /bmad-agent-pm (PRD)          → functional requirements, user journeys
3. /bmad-agent-architect         → stack decisions, ADRs, data model
4. /bmad-create-epics-and-stories → epic map + story list
5. /bmad-sprint-planning         → readiness gate → sprint-status.yaml (PASS required)
   ↓
6. /bmad-build <story-id>        → per story: clarify → implement → review → report
   OR
   /bmad-build-auto              → autonomous multi-story loop
7. /bmad-review                  → post-sprint retrospective
```

Step 5 must output PASS before step 6 begins. A CONCERNS output requires resolving the gap first.

## New Repo Checklist (BMAD addition)

In addition to the conventions.md repo standardization checklist, every new custom-built repo must:

- [ ] Run `npx bmad-method install --directory . --modules bmm --tools claude-code --yes`
- [ ] Add `_bmad/`, `_bmad-output/`, `.claude/` to `.gitignore`
- [ ] Create `docs/project-context.md` (stack, compliance, domain model, sprint state)
- [ ] Complete steps 1–5 above BEFORE writing any story implementation code
- [ ] Add SPRINT-OVERVIEW.md to the relevant sprint directory in minicloud-gitops
